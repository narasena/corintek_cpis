# Summary Report MVP Implementation Plan

## Goal
Deliver a printable, multi-page monthly Summary Report per project that includes:
1) Cover Page
2) Table of Contents
3) Bab I — Executive Summary Report
4) Bab II — Log Sheet Reports
5) Bab III — Analisa Laboratorium
6) Bab IV — Work Reports
7) Bab V — Chemical Reports

The report is rendered as web pages optimized for browser print (no PDF engine).
Client attachments are handled as a separate Attachment Pack flow and printed separately.

## Current WIP Snapshot
Existing implementation already provides:
- Summary Report selector UI and creation flow
- Summary Report print route with cover page, table of contents, and basic per-section lists
- Service layer for month filtering and summary aggregation

Key files:
- Summary report selector page: src/app/(main)/summary-reports/page.tsx
- Print page: src/app/(main)/summary-reports/[projectId]/[period]/print/page.tsx
- Actions: src/features/summary-reports/actions.ts
- Services: src/features/summary-reports/service.ts
- Prisma model: prisma/schema/summary-reports.prisma

Gaps vs desired behavior:
- Bab II/III/IV currently show summary lists, not the full printable pages of each report type
- Chemical section is aggregated summary, not detailed monthly usage pages
- No explicit Table of Contents numbering aligned with actual included pages
- No integration with existing print layouts for log sheets, lab analysis, and work report details

## Constraints
- No PDF generation backend
- Use browser-native print (print CSS/Tailwind print: modifiers)
- A4 layout, 210mm x 297mm, multi-page flow
- Server Actions only for internal data
- Use existing feature services and Prisma relations

## Inputs → Process → Outcome (BDD)
### Input
- Project selection (projectId)
- Period (YYYY-MM, default monthly)
- Section toggles (Bab I–V)
- Optional notes
- Optional attachment uploads (data temuan, blowdown, suhu, surat jalan)

### Process
- Normalize period to first day of month in UTC
- Upsert SummaryReport config (per project, per month)
- Fetch monthly data using service layer
- Render a print-optimized page tree with per-section content
- Store attachment URLs for separate Attachment Pack

### Outcome
- /summary-reports/[projectId]/[period]/print renders a multi-page report with the selected sections
- Browser print dialog is used to save/print
- Cover, TOC, and section pages are in the required order
- Attachment Pack is accessed separately and printed separately (no merging)

## Implementation Plan

### 1) Validate existing flow and stabilize inputs
1. Keep summary-reports/page.tsx as the entry point for report generation.
2. Ensure the month input always submits YYYY-MM and is converted to UTC month start in the action.
3. Persist section toggles and notes in SummaryReport so the print page is deterministic.

### 2) Define report section rendering strategy
Use existing feature print layouts where possible to avoid rebuilding templates:
- Log Sheets: use existing log sheet detail/print layout as sub-sections
- Lab Analysis: reuse LabAnalysisPrint component for each monthly lab analysis
- Work Reports: reuse WorkReportPreview layout per report
- Chemical Reports: keep monthly aggregated totals or extend to show per-log-sheet usage blocks

Decision for MVP:
- Bab II–IV should embed the existing print sections for each record in the month.
- Bab V shows a monthly chemical usage summary table (per chemical).
- Client attachments are separated from the autogenerated report into an Attachment Pack.

### 3) Data fetching design (server-side)
Use existing functions in src/features/summary-reports/service.ts:
- getMonthlyLogSheets(projectId, period)
- getMonthlyLabAnalyses(projectId, period)
- getMonthlyWorkReports(projectId, period)
- getMonthlyChemicalUsageSummary(projectId, period)

Ensure:
- Date range uses UTC month boundaries
- All related entities used in print view are included (project, client, parameters, photos, etc.)

### 4) Print page layout upgrade
Update src/app/(main)/summary-reports/[projectId]/[period]/print/page.tsx

#### 4.1 Cover Page
- Keep current cover page design
- Include: project name, client name, month label
- Force full A4 height with min-h-[297mm]

#### 4.2 Table of Contents
- Generate TOC items based on included sections
- Ensure TOC reflects real order

#### 4.3 Bab I — Executive Summary
- Keep counts (log sheets, lab analyses, work reports, chemicals)
- Add notes block if provided
- Optional: add per-machine summary later (non-MVP)

#### 4.4 Bab II — Log Sheet Reports
- Replace list with embedded printable pages per log sheet
- Strategy:
  - For each monthly log sheet, render the existing log sheet print component/page body
  - Ensure each log sheet starts on a new page (break-before-page)
  - Include photos if the log sheet print layout supports it

#### 4.5 Bab III — Analisa Laboratorium
- Replace list with embedded LabAnalysisPrint per analysis
- Each lab analysis starts on a new page

#### 4.6 Bab IV — Work Reports
- Replace list with embedded WorkReportPreview per report
- Ensure each work report starts on a new page

#### 4.7 Bab V — Chemical Reports
- Show monthly summary table from getMonthlyChemicalUsageSummary
- Use a compact table layout to fit in one page if possible

### 4.8 Attachment Pack (separate flow)
- Provide a separate page/section for client attachments
- Image attachments can be printed on their own pages
- PDF attachments are listed as download/open links with a note to print separately

### 5) Add summary report section wrappers
- Create small wrapper components in the print page for each chapter
- Each chapter:
  - Starts on a new page
  - Uses consistent section title
  - Handles empty data with localized empty state

### 6) Integration with existing print components
Update src/app/(main)/summary-reports/[projectId]/[period]/print/page.tsx

Use existing components:
- Log sheet print component (verify actual path under src/app/(main)/log-sheets/...)
- LabAnalysisPrint from src/features/lab-analyses/components/lab-analysis-print.tsx
- WorkReportPreview from src/app/(main)/work-reports/[projectId]/[workReportId]/components/work-report-preview.tsx

If a log sheet print component does not exist, implement a shared LogSheetPrint in src/features/log-sheets/components/ that:
- Accepts LogSheetDetail data
- Uses A4 print layout consistent with existing log sheet detail page

### 7) Navigation and print UX
- Keep PrintButton and back navigation hidden in print mode
- Ensure layout uses print:hidden, print:p-0, print:bg-white
- Ensure each chapter starts on a new page using break-before-page

### 8) Verification checklist
- Load Summary Report page, select project + month, include all sections
- Print preview shows:
  - Cover page
  - TOC
  - Bab I–V in correct order
  - Each report starts on a new page
- Empty data states render cleanly without layout overflow
- Attachment Pack shows uploaded files and supports separate print

## Localization
- All labels use Indonesian (as existing pages do)
- Cover: Laporan Ringkas Bulanan
- TOC: Table of Content
- Bab labels: Bab I — ..., etc.

## Risks and Mitigations
- Risk: large monthly data causes huge print pages
  - Mitigation: strict break-before-page per record and paginate in print
- Risk: inconsistent timezone for monthly filter
  - Mitigation: use UTC month start in server action and service
- Risk: missing print layout for log sheets
  - Mitigation: build a shared print component and reuse in summary report
- Risk: client expects merged PDFs
  - Mitigation: make Attachment Pack separate with clear "print separately" guidance
